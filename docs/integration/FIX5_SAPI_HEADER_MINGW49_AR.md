# Fix 5 — إزالة مرجع Windows Speech API غير المستخدم من سورس المحرك المولّد

## سبب توقف البناء

يؤكد سجل Windows المرسل أن مكتبة 7-Zip والمكتبات المساعدة Boost.Filesystem وWebP تجاوزت مرحلة التجميع، لكن تجميع المحرك الأصلي توقف في `source/system.cpp` عند:

```text
fatal error: sapi.h: No such file or directory
```

يتضمن السورس المربوط من النسخة المثبتة `source/system.cpp` الهيدر `#include <sapi.h>`، لكنه لا يستخدم أي رمز من واجهة Windows Speech API (SAPI). حزمة MinGW 4.9.2 مع Qt 5.6.3 لا تقدم الهيدر المذكور.

## التنفيذ

1. التحقق من بصمة Git blob كاملة لـ `source/system.cpp` للمصدر المحدد `25468bdb...` قبل تعديل أي نسخة.
2. إضافة تعديل محكوم بعدد ظهور واحد في `patches.json` يزيل **سطر التضمين غير المستخدم فقط** في النسخة المولّدة `vendor/origin-patched/source/system.cpp`، دون تعديل `vendor/origin-upstream` أو ملفات نسخة SDIO الرسمية عندك.
3. إزالة استيراد `-lsapi` غير اللازم من مرحلة الربط، حتى لا يفشل الرابط لاحقًا بحثًا عن ملف مكتبة غير مستخدم.
4. إضافة فحص مسبق في `build_native_engine.ps1` يمنع استمرار البناء إذا بقي الهيدر غير المتوافق في نسخة سورس المحرك المولّدة.
5. إضافة اختبارين بنيويين لتثبيت التعديل.

## طريقة التركيب

- استخدم Hotfix ZIP، وفك محتوياته مباشرة داخل مجلد المشروع الحالي، مع الاستبدال بالموافقة.
- **لا تحذف** مجلدات `vendor`، `.source-cache` أو `build-origin-matching`؛ السكربت يُعيد توليد `origin-patched` وحده من النسخة الموثقة، ويحتفظ بالمصادر المحمّلة والمكتبات المتجمعة.
- شغل `01_BUILD_ENGINE_MATCHING.cmd` لاختبار بناء الفحص والمطابقة؛ **لا** تشغل اختبار التثبيت الآن.

## حدود الاختبار

هذا إصلاح لسطر تضمين غير مستخدم وخيار ربط، وقد اجتاز اختبارات بنيوية محلية؛ لا يعني اعتماد تجميع المحرك النهائي أو تشغيله على Windows أو سلامة تثبيت التعريفات. نجاح البناء يحتاج تأكيدًا من Windows MinGW عندك.
