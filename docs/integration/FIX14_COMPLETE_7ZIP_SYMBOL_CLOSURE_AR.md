# Fix 14 - حل جذري لقائمة ربط 7-Zip الناقصة

## المشكلة الفعلية

بعد 13 إصلاحًا متتابعًا، كل محاولة Windows كانت تتوقف في نفس مرحلة
الربط بسبب ملف تنفيذ من 7-Zip غير مُدرج في `project/7zip/lib.cbp` القديم.
آخر خطأ بعد Fix 13 هو `CBZip2Crc::Table`، وتعريفه الأصلي في
`CPP/7zip/Compress/BZip2Crc.cpp`.

تمت مراجعة شجرة Git للمصدر المثبّت: المجلدان C وCPP يحويان 271 ملف
C/C++، بينما مشروع Code::Blocks القديم يُدرج 174 ملفًا منها، وFix 13
يضيف 15 ملفًا أخرى. **هذه الأرقام ليست دعوة لتجميع كل المصادر**؛
بعض الملفات تخص واجهات أو برامج DLL مستقلة، وقد تعطل البناء إذا أضفناها.

## الطريقة الجديدة

1. إضافة `BZip2Crc.cpp` الأصلي ببصمة Git محددة.
2. حفظ بيانات Git SHA-1 لـ 82 مصدرًا ناقصًا في `7zip-source-catalog.json`.
3. بعد بناء مكتبة 7-Zip، فحص رموزها الحقيقية بـ `nm.exe` من نفس MinGW.
4. اختيار ملف تنفيذ جديد فقط عند وجود **تعريف مطابق واحد وواضح**
   وبصمة Git صحيحة وتطابقه مع النسخة الأصلية غير المعدّلة.
5. إعادة بناء المكتبة تلقائيًا لحد 14 دورة تصحيح داخل تشغيل واحد،
   بدل مطالبة المستخدم بتكرار تنزيل Hotfix عند كل رمز ناقص.
6. استبعاد الملفات الخاصة بـ DLL والتطبيقات المستقلة والتحكم في النوافذ
   من الإضافة التلقائية. لا تغيير لـ `--whole-archive` أو وظائف فك الضغط.
7. تقرير الأجزاء المضافة يُكتب إلى
   `build-origin-matching/7zip-closure-report.txt`.

## الحدود الصريحة

هذا **تحسين آلي لاختبار مصادر 7-Zip** وليس ضمان نجاح EXE.
التعرف التلقائي متحفظ؛ قد يفوّت دالة معرفة عبر ماكرو، أو اختيارًا مركّبًا،
وقد يبقى مصدر مفقود غير موجود في المصدر المثبّت. يجب اختبار نتيجة
Windows على جهاز المستخدم، ثم اختبار الوظائف الحقيقية على جهاز معزول.
ما زال تثبيت التعريفات الحقيقي غير مفعّل في إعداد matching.

## التركيب

فك ملف Hotfix فوق مجلد `SDIO_Modern_Origin_Integration_Candidate` الحالي
مع الاستبدال، ولا تحذف vendor أو .source-cache أو build-origin-matching.
شغّل فقط `01_BUILD_ENGINE_MATCHING.cmd`.
